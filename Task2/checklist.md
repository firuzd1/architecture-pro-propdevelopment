# Проверочный лист безопасности бизнес-систем PropDevelopment

## Почему выбраны именно эти разделы

В системе есть три ключевые проблемы: показ чужих данных клиентам, небезопасные API партнёров и отсутствие контроля потоков данных. Поэтому выбраны разделы: управление доступом, защита данных, безопасность API и аудит. Это закрывает самые критичные уязвимости перед аудитом.

## 1. Управление доступом

| № | Проверка | Статус | Комментарий |
|---|---------|--------|-------------|
| 1.1 | Реализован принцип минимальных привилегий для всех пользователей | Частично | нет системного контроля доступа к данным |
| 1.2 | Настроена многофакторная аутентификация для сотрудников | Неизвестно | не описано в архитектуре |
| 1.3 | Разграничен доступ между доменами (продажи, ЖКУ, финансы, дата) | Частично | домены не изолированы на уровне данных |
| 1.4 | Партнёры не имеют доступа к данным других партнёров | Нет | зафиксированы случаи когда партнёр одной УК видит данные другой |
| 1.5 | Клиенты видят только свои данные в личном кабинете | Нет | есть жалобы на показ чужих данных |
| 1.6 | Доступ через firewall настроен для внешних пользователей | Да | описано в архитектуре |

## 2. Защита персональных данных (152-ФЗ)

| № | Проверка | Статус | Комментарий |
|---|---------|--------|-------------|
| 2.1 | Ведётся реестр обрабатываемых персональных данных | Неизвестно | не описано |
| 2.2 | Получено согласие клиентов на обработку ПД | Неизвестно | не описано |
| 2.3 | Данные клиентов зашифрованы при хранении | Неизвестно | не описано |
| 2.4 | Трафик с ПД передаётся только по зашифрованным каналам | Неизвестно | не описано явно |
| 2.5 | Биометрические данные (домофон) обрабатываются по отдельному согласию | Нет | новые сервисы умного дома ещё не внедрены, политика не описана |
| 2.6 | Настроено резервное копирование БД с ПД | Да | описано в архитектуре |

## 3. Безопасность API партнёров

| № | Проверка | Статус | Комментарий |
|---|---------|--------|-------------|
| 3.1 | Все API партнёров используют единую политику аутентификации | Нет | нет единых политик безопасности |
| 3.2 | Контракты API не содержат лишних персональных данных | Нет | выявлены контракты с избыточными ПД |
| 3.3 | Партнёры не могут выполнять действия за пределами своих полномочий | Нет | партнёр может изменить данные чужих клиентов |
| 3.4 | Все интеграции с партнёрами задокументированы | Частично | документация неполная |
| 3.5 | Есть API Gateway для контроля трафика к партнёрам | Нет | не описан в архитектуре |
| 3.6 | Проводится регулярный аудит контрактов API партнёров | Нет | не описано |

## 4. Аудит и мониторинг

| № | Проверка | Статус | Комментарий |
|---|---------|--------|-------------|
| 4.1 | Все действия пользователей логируются | Неизвестно | не описано |
| 4.2 | Настроены алерты на подозрительную активность | Неизвестно | не описано |
| 4.3 | Специалист по ИБ получает уведомления об изменениях в системах | Нет | описано что специалист не получает все изменения |
| 4.4 | Проводятся регулярные проверки безопасности | Нет | аудит только планируется |
| 4.5 | Ведётся журнал доступа к персональным данным | Неизвестно | не описано |

## 5. Управление данными

| № | Проверка | Статус | Комментарий |
|---|---------|--------|-------------|
| 5.1 | Определены владельцы данных для каждого домена | Неизвестно | не описано |
| 5.2 | Потоки данных между системами задокументированы | Нет | внутренние потоки не контролируются системно |
| 5.3 | Нет дублирования точек регистрации клиентов без координации | Нет | несколько точек регистрации без координации |
| 5.4 | Данные группы Дата не имеют неограниченного доступа к ПД | Нет | нет ограничений на доступ к данным со стороны систем обработки |
| 5.5 | Определена политика хранения и удаления данных | Неизвестно | не описано |
